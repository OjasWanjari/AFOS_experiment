## 2. 関数別の解釈

### 論文08: atanの微分内の二乗でオーバーフロー

関数:

`(tanh(x) + max(x,0)) * sigmoid(softplus(x) * erf(atan(x)))`

[error.txt](../AFOS_diagnostics/published/diagnostics/paper_08_seed_0/check/attempt_0001/error.txt) のスタックに `_AtanGrad` があり、`gradient_tape/.../paper_activation_5_1/Square_1` で停止している。二乗の入力は第6畳み込み層の `BiasAdd` 出力。

数学的には `d atan(x)/dx = 1/(1+x²)`。float32の最大有限値は約 `3.4×10^38` なので、有限な入力でも `|x|` が約 `1.84×10^19` を超えると二乗が表現範囲を超える。今回はその二乗で +Inf を検出した。

停止前の記録済み学習lossは `37.59 → 264.96 → 461,457.97` と急増。停止後の重みはすべて有限だが、最大絶対値が **約1.42×10^20** に達している。単なる通常の丸め誤差という規模ではなく、学習値が極端に大きくなった証拠がある。

ただし `x² = Inf` でも `1/(1+Inf) = 0` となり得る。**「微分の中間値がInf」から「最終的な勾配がNaN」「元の失敗原因はこの二乗だけ」とは断定できない。** replayの追加と、中間値・最終勾配を区別した記録が必要。

### 論文10・12、ELU: 畳み込み出力でInf、学習値の急増

関数:

- 論文10: `max(sin(x)*sigmoid(sin(x)), x*erf(x)+tanh(x))`
- 論文12: `x*erf(x)+sin(x)`
- ELU: `x`（正側）、`exp(x)-1`（負側、alpha=1）

いずれも今回checkが報告したのは活性化関数内ではなく、**畳み込みの積和計算の出力**。停止直前の記録済み学習lossは次のとおり。

| 対象・モード | 記録済みlossの推移（最後の3～4値） |
|---|---|
| 論文10・check | 16.72 → 62.77 → 499.30 → 1.91×10^9 |
| 論文12・check | 15.79 → 91.28 → 2,828.36 → 6.52×10^14 |
| ELU・check | 94.10 → 541,305.56 → 5.66×10^20 |
| ELU・replay | 6,894.16 → 1.59×10^16 → NaN |

これらは `batches.jsonl` のKeras集計lossであり、**各バッチ単独のlossとは限らない**。

損失の急増、極端な有限重み、NaN化した重み・SGD momentum状態は、学習が数値的に発散したという解釈を強く支持する。大きな活性値・重み・勾配更新が互いに増幅し、float32の表現範囲を超えた可能性が高い。ただし生の勾配や各層入力を保存していないため、どの更新が発散を始めたかは未確定。

学習率0.01・momentum 0.9は固定されているが、これらが単独の原因だったと判断する比較実験はまだない。**ELUの負側のexpそのものがオーバーフローした、という結果ではない。** 今回のELUの検出位置は畳み込みである。

### 論文11: 順伝播のsinhでInf

関数:

`(tanh(x) + max(x,0)) * sigmoid(softplus(x) * erf(sinh(x)))`

[error.txt](../AFOS_diagnostics/published/diagnostics/paper_11_seed_0/check/attempt_0001/error.txt) は第5活性化層の `Sinh` 出力の ±Inf を記録している。sinhは入力の絶対値に対して指数的に増大するため、大きい入力でオーバーフローする。

ただし関数全体には `erf(sinh(x))` があり、順伝播では `erf(±Inf)=±1` へ飽和し得る。一方、連鎖律に現れる `erf'(sinh(x))*cosh(x)` は数値的に `0*Inf` に相当する不定な計算になる可能性がある。**これは有力な計算経路の仮説であり、このログでその積を検出したわけではない。** 保存後の重みにNaNがあることも、これだけで因果順序を確定する材料にはならない。

### 論文13: 失敗は2回再現、演算の特定は未実施

関数: `max(x,erf(x))`。

replayの2試行とも第9バッチで学習lossがNaN。attempt 1では直前に `3,663.67 → 9.02×10^8 → NaN`、attempt 2では `3,892.61 → 8.66×10^8 → NaN` となった。両方でモデル重みとmomentum状態の全要素がNaN。

**戻されたフォルダにはpaper_13のcheck結果がなく、replayが2回ある。** 再現性のある発散は確認できるが、初めに問題になる演算は未特定。expやsinhを含まない関数でも、ネットワーク全体の学習過程で数値異常が起こることを示している。

### 今回の候補13: checkでは再現しなかった

関数: `atan(x)*min(x,0)+tanh(x)`。上記の論文13とは別の関数。

[result.json](../AFOS_diagnostics/previous/diagnostics/discovered_13_seed_1/check/attempt_0001/result.json) では50エポック、35,200学習バッチを完了し、全モデル重みとmomentum状態が有限。

| 指標 | 診断実行の最終値 |
|---|---:|
| 学習accuracy / loss | 86.3756% / 0.383498 |
| 検証accuracy / loss | 80.9000% / 0.605185 |
| テストaccuracy / loss | 81.1500% / 0.618287 |

この成功は、元の50エポック目の失敗が「解消した」ことを意味しない。checkによる計算グラフの変更などで学習経路が変わった可能性がある。paper_13の同seed・同モードのreplay同士でもlossの値は完全には一致しておらず、この一連の実行でビット単位の再現性は確認できていない。GPU演算の非決定性などの寄与は候補であって、今回の資料だけでは原因を特定できない。

**診断のテスト81.15%で元の失敗結果を置き換えたり、正式なTop15平均へ混ぜたりしない。** まず今回の候補13のreplay結果が必要。

## 4. ログを読む際の注意

- **OOMによる終了は今回の9試行には記録されていない。** 戻された結果の分類とログはNaN/Infによる停止、または完走を示す。以前のGPUメモリ不足とは分けて扱う。
- `layout failed ... LayoutOptimizer` は全9試行にあり、50エポック完走した候補13にもある。このメッセージだけをNaNの直接原因とは判断できない。後続の学習が実行されている。
- replayの `result.json` の最後のcontextはvalidationだが、`batches.jsonl` ではその前のtrainでloss NaNが記録されている。**異常が検証時に始まったわけではない。** 学習打切り後も検証処理が走り、その最後のcontextが保存された。
- worker.logの `704/704` 表示だけで全704学習バッチを処理したと判断しない。callbackの記録では、失敗したreplayの学習終了バッチ数はpaper_13が9、ELUが14。
- lossがNaNでもaccuracyは有限のことがある。実際、失敗replayのvalidation accuracyは9.6%。accuracyが有限であることは数値的に正常なモデルである証拠にならない。
- 環境一致はチェック対象の範囲での一致。Python・TensorFlow/Keras等・GPU機種・TFビルド情報・指定したXLA設定などを比較しているが、GPUドライバの完全一致や演算の決定性まで保証しない。

## 5. 次の調査

まず不足している2つの実行を、元のLinux環境で、展開済み `AFOS_diagnostics/` を作業ディレクトリとして行う。既存の診断プログラムで実行できる。`--resume` は計画を再利用する指定であり、学習は最初から行い、新しいattemptへ保存する。

```bash
# 失敗が再現した論文13の演算単位の診断
python published/diagnose_retraining.py --output published --resume --trial paper_13_seed_0 --mode check

# checkでは成功した「今回の候補13」の通常再実行
python previous/diagnose_retraining.py --output previous --resume --trial discovered_13_seed_1 --mode replay
```

次に論文08・10・11・12のreplayを追加し、checkの停止と通常実行の発散を対応付ける。ELUと論文関数のseed 1～4、計24ケースは今回の戻された結果には含まれていない。

根本原因をさらに追う場合は別の診断実装で、異常直前のバッチに対して各層の入力・出力、更新前の重み、生の勾配、momentum更新後の値を順序付きで記録する。論文08ではatan微分の中間Infと最終勾配、論文11ではsinh→erfの順伝播と逆伝播を分ける。学習率変更・gradient clipping・数式の安定化は原因の切り分け後、条件を明示した別実験として比較する。
